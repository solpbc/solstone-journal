### 🔴 MEASURED SIDE EFFECT — `--dry-run` IS NOT READ-ONLY
################################################################################
###
### Fresh journal, tree captured before and after `think --day X --dry-run`:
###
###   BEFORE: <journal>/
###   AFTER:  <journal>/chronicle/20260101/
###           <journal>/identity/{health.md,history.jsonl,.identity.lock,partner.md}
###
### Two independent writers, both reached before anything is printed:
###   - the identity bootstrap, which runs in main() ahead of the whole refusal
###     matrix (same writer the argument-refusal path hits);
###   - the day directory, created inside the per-talent output-status helper,
###     because the path resolver it calls defaults to creating.
###
### BOTH HALVES ARE CONTRACT. A port that makes dry-run read-only stops creating
### directories a first run depends on; a port that creates more than these two
### exceeds the reference. Assert the exact set, in both directions.

################################################################################
### OUTPUT-PATH RESOLVER — known-answer validated, both directions
################################################################################
###
### Daily layout is  <day>/talents/<name>.<ext>  where <ext> comes from the
### TALENT'S DECLARED OUTPUT FORMAT, not from any file found on disk. App-scoped
### keys mangle: "app:name" -> "_app_name".
###
###   baseline .................. all three daily gens report (new)
###   place talents/morning_briefing.json ... ONLY morning_briefing -> (exists)
###   place talents/daily_schedule.md  ...... NO CHANGE (that talent is json)
###
### The third line is the negative control and it is the one worth keeping: it
### fails if an implementation resolves the status by listing the directory
### instead of constructing the path. A resolver that matches on stem alone
### passes the second line and fails this one.
###
### Status vocabulary: " (exists)" | " (new)" | "" (empty for the <each> target).
