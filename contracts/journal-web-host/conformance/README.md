# Journal import host conformance

Run `python3 serve.py` from this directory and load its printed loopback address through the platform's test host. On a Linux test desktop, `python3 serve.py --viewer /usr/bin/solstone-linux-journal` starts the viewer too. Use an isolated test account and daemon queue for picker checks. The fixture server serves test files only. Use a disposable paired journal for the upload and history checks. Open index.html through the app's normal journal window and run each control. The browser run reports an absent host. Open the journal's import page there and upload sample.txt through its regular file input.

The host advertises the generated version and supported request types on the top journal document. It accepts a JSON object and resolves a JSON reply with the same id. Ignore unrecognised fields and answer unrecognised types with unsupported. Never infer support from a user agent. An embedded document must have no host capability. A host that disables frames can verify this using its frame policy and a frame-load observation in its integration suite.

import.pick carries the import area, a list of picker filters, a multiple-selection flag and a context object. The filters guide the picker. Store a durable copy before reporting queued. Each accepted entry in items carries a device-queue item ID and the original display name. A mixed selection also reports individual failures in refused with a name and optional reason. A selection that saves nothing reports refused. Dismissing the picker reports cancelled. A competing intake reports busy. Send import.status events with the original request id, item ID, display name and state. States include waiting, uploading, attention and delivered. A journal row is identified by import_id. A local drop can use the same request with a short-lived, host-issued drop token, without exposing filesystem paths to the page.

In the saved journal record, check that setting was applied and that the complete context from cases.json was retained, including its nested future field. Repeat using a new sample, close the viewer after queued, and verify delivery in history. Exercise each import card through the same journal, including the Apple Health preview and confirmation, and verify a user-activated outside link opens in the system browser. Run the desktop checks once on direct pairing and once on the relay. Use unique sample contents on each run so content deduplication does not substitute an earlier row.
